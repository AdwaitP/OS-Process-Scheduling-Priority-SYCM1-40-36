What is Priority Scheduling?

Priority scheduling is an algorithm where the CPU is allocated to the process with the highest priority. It is a fundamental concept in operating systems designed to ensure that important tasks are executed before less important ones. Priorities can be defined internally (e.g., memory requirements, time limits) or externally (e.g., user importance, political factors).

Convention: In our simulator and many textbook examples, a lower number indicates a higher priority. For instance, Priority 1 > Priority 5. Equal-priority processes are scheduled in First-Come, First-Served (FCFS) order.

1. Non Pre-emptive

Once the CPU has been allocated to a process, the process keeps the CPU until it voluntarily releases it (by terminating or waiting for I/O). Even if a newly arrived process has a strictly higher priority, it must wait in the ready queue until the current process finishes execution.

2. Pre-emptive

If a newly arrived process has a higher priority than the currently running process, the CPU is forcibly preempted (taken away) from the current process. The current process is placed back in the ready queue, and the CPU is immediately given to the new, higher-priority process.

The Major Problem: Starvation

A major flaw in priority scheduling algorithms is indefinite blocking, or starvation. A process that is ready to run but lacking the CPU can be considered blocked. In a heavily loaded computer system, a steady stream of higher-priority processes can prevent a low-priority process from ever getting the CPU.

The Solution: Aging

Aging is a technique used to overcome starvation. It involves gradually increasing the priority of processes that wait in the system for a long time. For example, if priorities range from 127 (low) to 0 (high), we could decrease the priority number of a waiting process by 1 every 15 minutes. Eventually, even a process with an initial priority of 127 will reach priority 0 and be executed.

Advantages

  • Simplicity in design and ease of understanding.
  • Ensures critical, high-priority processes run immediately without waiting for long, unimportant tasks.
  • Highly flexible; priority formulas can be adjusted based on dynamic system needs (time limits, memory).

Disadvantages

  • Vulnerable to Starvation if aging is not implemented.
  • Susceptible to Priority Inversion (where a low-priority process blocks a high-priority process by holding a shared resource).
  • Overhead: Pre-emptive mode can cause frequent context switches if high-priority tasks arrive constantly.
